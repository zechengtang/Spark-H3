# Reblock 消融实验 Prompt

请基于 blog Table 3/4 的 `spark-h3-10pct` 设置执行 reblock 消融。先查阅 `docs/blogs/spark-attn/README.md` 及对应实验配置／运行脚本，确认实际设置，不要仅根据表格猜测参数。

## 固定设置

- 沿用 `spark-h3-10pct` 的 Top-K 10%、Q64×K64 exact tile、mean route、近似支路、warmup、精度和其余推理设置。
- 固定 fanout=16（各级最大 fanout）。初始顺序默认 flat，仅在初始顺序消融组中改为 hilbert_thw 或 tile_t4h4w4；其他组保持 flat。
- 使用 5s768p 作为 10s768p 的快速代理，其余设置不变。相同 prompts、seed 和 Dense 参考用于所有候选。
- 仅修改 reblock，不改路由分数、近似支路或生产默认配置。

## 消融项

先检查当前实现，明确“类簇中心选择方式”涉及的是选种子／代表点还是迭代中心更新，分别命名，避免混为一个变量。

以当前实现为唯一 baseline。M2 加权与距离类型明确做一组 2×2 消融，以验证交互；其余轴每次只改变一项：

1. M2 加权 × 聚类距离：完整测试双方 M2 加权＋cosine（baseline）、双方 M2 加权＋Euclidean、不加权＋cosine、不加权＋Euclidean 四组。固定 fanout=16、flat、32 个 midpoint landmarks、2 次中心更新、中心选择／更新规则、Top-K 10% 和近似支路。分析 cosine 的优势是否依赖 M2，以及 M2 对两种距离的作用是否不同。已有结果只有在代码、采样、尾部保护和预算一致时才能复用；必须补齐不加权 Euclidean，不能由另外三组推断。
2. 保留 Q 侧单独加权、K 侧单独加权的补充对照，先固定 cosine，不自动扩展为全部组合。Q 侧单独加权指只对 Q 聚类特征施加对侧 K 的 M2；K 侧同理，另一侧仍参与 reblock，但使用未加权特征。这组只改变加权侧别，不改变 M2 估计方法。
3. 类簇中心选择／更新规则：当前方法 vs 少数明确的替代方法。先说明候选定义及计算成本，再运行；固定更新次数，避免与下一组混淆。
4. Landmark 数量：32（baseline）／64/128，保持 midpoint 选取方式和中心更新 2 次不变；不改变最终 64-token block 或 exact tile。确认参数实际传入所有相关实现路径；若某路径不支持 64，明确报告并实现一致支持，不静默改成其他数量。
5. 中心更新次数：0／1／2（baseline）／4，保持 landmark 数量 32、初始种子和更新规则不变。次数指每个 proxy 二分节点在 landmarks 上的“分配＋中心更新”轮数；最终全 token 打分及容量约束划分始终执行。
6. M2 估计方式：当前 Hilbert midpoint 采样（baseline）／原始 flat64 块均值外积／flat64 等间隔 midpoint 采样（每块 1／2／4 个真实 token）／flat64 块均值＋精确对角方差补偿／全部 video token 的完整二阶矩。保持 M2 加权开启、cosine、非中心化定义及相同 ridge 系数，其他设置不变。这组与“M2 有无”分开，不交叉展开。
7. Q/K 重排复用：当前 Q、K 独立重排（baseline）／Q 侧复用 K 侧重排／K 侧复用 Q 侧重排。复用的是相同原始 video token 索引空间中的最终置换，不是将 Q/K 数值或聚类特征相互替换；Q 复用 K 时只构造 K 布局，反向同理，V 始终跟随最终 K 布局。验证完整置换、尾部、K/V 同步和 Q 输出逆置换；明确共享布局下尾部身份的处理，并记录两侧实际保护 token，不能静默混入尾部变化。分别比较 attention 质量和包括省去一侧布局构造在内的完整成本，不只在双侧都计算后复制索引来计时。
8. 每个子序列的 landmark 压缩方式：midpoint（baseline）／子序列均值／子序列在对侧全局均值点的泰勒 0＋1 阶代表。沿当前节点 token 顺序切出用于构造 landmarks 的连续子序列，每段压缩为一个代表；子序列长度由节点长度和本组固定的代表数量决定，不固定为 64。三种方法使用完全相同的子序列边界、代表数量和长度权重。第一层使用 flat 初始顺序，后续层沿节点继承顺序继续切分与压缩；所选压缩方式在所有待分裂层生效。只改变压缩方法，保持 M2 采样、距离、fanout、中心更新和 attention 支路不变。
9. Token 初始顺序：flat（baseline）／hilbert_thw／tile_t4h4w4。该轴只改变 root 的初始 token 顺序，后续保持 parent_order；固定当前 midpoint landmark 压缩、M2 的 Hilbert midpoint 采样及其他设置。核对 tile_t4h4w4 的实际索引与 FastH3 侧一致，不能只依据名称。初始顺序、M2 采样、landmark 压缩三者独立，不随初始顺序自动改变 M2 采样，也不把三组展开为全因子组合。

第 8 组与第 6 组的 M2 估计消融是不同实验，不同时修改两处。每个子序列的均值代表为其原始 Q/K 均值 `mu`；泰勒代表为 `mu + C*a/sqrt(D)`，其中 `C=mean((x-mu)*(x-mu)^T)`，均值按该子序列实际长度计算。通过 `mean((x-mu)*dot(x-mu,a))/sqrt(D)` 计算修正，避免显式构造 D×D 协方差。Q 代表使用 K 的全局均值锚点，K 代表使用 Q 的全局均值锚点；锚点分别按 batch/head 对全部原始 video tokens 求均值，包含余数、不包含 context，不使用节点局部均值。所有树层共享本次 reblock 输入对应的全局锚点。

锚点构造及原始 Q/K 的数据口径参考当前 global reweight 实现，记录实际精度与缩放；块代表在原始 Q/K 空间构造，再沿用该侧当前 M2 特征变换。泰勒式来自块内指数权重的 0＋1 阶近似，不以完整 softmax 加权摘要替代，不改变生产 global reweight 支路。

压缩组保持 baseline 的子序列边界及 landmark 数量策略，不额外引入 flat64 候选块选择。当前生产默认 landmark 目标数为 32，而最大 fanout 为 16，两者不是同一参数；若测试“子序列数等于实际 fanout”，应单列数量对照，不能静默与压缩方法同时改变。记录逐层实际子序列数量、长度、代表权重、代表构造时间、完整 reblock 成本和质量，并验证所选压缩方式在后续层实际生效。

M2 估计方式的实现要求：

- 所有估计使用相同的原始 video Q/K 范围，包含余数 token、不包含 context；Q 使用 K 的矩阵，K 使用 Q 的矩阵。
- flat64 块均值估计为 `sum_b (n_b/N) * mu_b * mu_b^T`，按原始 flat 顺序分块，余数作为一个短块参与并按实际长度加权。它丢弃块内方差，是近似 M2，不是完整矩阵。
- flat64 等间隔 midpoint 采样：按原始 flat 顺序分块，每块确定性选择 `s_b=min(m,n_b)` 个真实 token，`m=1/2/4`；块内零基索引为 `floor((j+0.5)*n_b/s_b)`，`j=0,...,s_b-1`。完整 64-token 块对应 `[32]`／`[16,48]`／`[8,24,40,56]`；余数块按相同公式处理。估计为 `sum_b (n_b/N) * (sum_sample x*x^T / s_b)`。无随机抽样、无采样 seed；保存索引并验证唯一性和范围，所有候选共享原始 flat 分块，不从 reblock 后的块采样。这是可复现的确定性近似，不声称统计无偏；不同采样数量不要求索引嵌套。复杂度约为 `O((mN/64)*D^2)`；记录实际样本数及采样开销。
- flat64 块均值＋精确对角补偿：先计算块均值 M2，再加上 `Diag(mean_all(x*x) - sum_b (n_b/N)*mu_b*mu_b)`，这里 `x*x` 是逐元素平方。补偿完整 M2 的对角线，仍忽略块内非对角相关性；复杂度为 `O(ND+(N/64)*D^2)`。用小样本参考验证对角一致性；记录归约精度及浮点负方差的处理，不掩盖显著数值异常。
- 完整 M2 为 `X^T X / N`，允许用 GPU 矩阵乘法分块累加；不构造 N×N 矩阵，不减去均值。用小样本 FP32 参考验证分块累加结果，并记录输入、乘法及累加精度。
- ridge 按每种估计自身的 trace／维度缩放，沿用相同系数和分解方式；冻结共同保护尾部身份，避免估计差异混入尾部保护收益。
- 分别记录 M2 构造时间和完整 reblock 时间，并结合完整生成的质量指标评估；不能只比较矩阵误差或忽略完整 M2 的额外成本。

完整 M2 可先在较小的完整生成样本上评估，再扩大生成样本。上述估计不改变后续完整矩阵特征变换，其成本仍为 `O(ND^2)`。低秩 sketch（例如 Frequent Directions）暂列为后续可选方向，不进入首轮；若启动，需单独定义秩、误差与变换实现，不与当前单轴结果混为同口径。

0 次更新定义为直接使用初始种子构造分裂方向，仍正确生成后续 proxy 子节点所需的 landmark 分配，并完成最终容量约束划分。不能简单将当前循环设为 0，否则子节点分配可能无效。为 0 次路径补充容量、置换和子节点分配测试。

Landmark 数量和更新次数分别做单轴实验，不交叉展开 3×4 组合；共用同一个 32-landmark、2 次更新的 baseline。记录实际每个节点使用的 landmark 数量与更新次数，同时比较质量和完整 reblock 耗时。

这里的 M2 加权是当前生产实现的对侧非中心化二阶矩变换，不是逆协方差 whitening。原始 attention Q/K/V 不变。

除上述明确指定的 M2×距离 2×2 外，不做所有轴的全因子组合。其余轴分别做单项完整生成评估；只有多个方案分别显示稳定收益时，才测试少数组合，以检查交互。当前实验固定 Top-K 10%，不能用它验证 SVG2 top-p 自适应保留密度的巨大差异；自适应路由属于另一个实验，不与本轮混算。

## 执行与评估

- 每个候选都从相同 seed 和 conditioning 独立运行完整视频生成。
- 扩大到至少 10 prompts，固定采样清单。调参样本与确认样本分开。
- 所有候选保持相同的块预算、尾部/context 保护、采样参数和输出口径。
- 完整生成报告相对于匹配 Dense 的 PSNR/SSIM，以及充分预热后的去噪耗时；条件允许时补充 LPIPS 和感知质量评估。
- 保存配置、代码版本、逐样本数据和失败日志。完整生成与计时使用独立记录，不声称已经验证 10s 迁移。

## 多 agent 分工

主 agent 负责制定并冻结实验配置、分配 GPU、监控子 agent 和日志、检查结果、分析结论及整理报告。

若干子 agent 负责具体实现、正确性测试和实验运行。所有子 agent 使用 `gpt-5.6-sol`，reasoning effort=`medium`；环境不支持时报告，不静默替换。按可用 GPU 和并发上限分配任务，计时期间避免同 GPU 并发干扰，各任务使用独立输出目录。

主 agent 定期汇报进度，并在验收数据完整性和比较口径后汇总结果。不要启动无关消融或擅自扩大组合。

最终将实验设置、结果表、质量—成本分析和下一步建议整理到 `docs/reblock_ablation_5s768p.md`，保留可复现脚本与原始记录。
