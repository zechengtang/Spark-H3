# H3 RoPE 中时间轴与空间轴的区别

MiniMax H3 为 packed sequence 中的每个 token 分配三维位置坐标 `(t, h, w)`，再使用三轴 RoPE 编码这些坐标。

## RoPE 计算本身

在 RoPE 层内部，三个轴的处理是对称的：

- `t`、`h`、`w` 各使用相同数量的频率；
- 三个轴共享同一组 `inv_freq` 和 `rope_theta`；
- 各轴生成的角度按 `[t, h, w]` 拼接后应用到 Q 和 K。

因此，三轴的核心差异不在旋转公式，而在输入 RoPE 的位置坐标如何构造。

## `h/w`：相对空间坐标

H3 不直接把 latent 网格索引 `0, 1, 2, ...` 当作空间位置，而是按照 latent 画面的面积和宽高比进行归一化：

```text
h_range_scale = H / sqrt(H * W)
w_range_scale = W / sqrt(H * W)
```

坐标随后被居中并乘以固定尺度 `32`。

这意味着：

- 在宽高比相同、分辨率不同的情况下，`h/w` 坐标范围基本一致；
- 更高的分辨率主要增加坐标采样密度，而不会按分辨率同比放大坐标范围；
- 宽高比变化时，`h` 和 `w` 的范围会相应变化，以保留画面的几何比例；
- 正方形画布的两个空间轴大致覆盖 `[0, 32)`，而不是 `[0, 1]`。

因此，不能仅因为条件视频和目标视频的分辨率不同，就按分辨率比例再次缩放条件视频的 `h/w` RoPE 坐标。这样会重复引入尺度变化，破坏原有的空间归一化。

## `t`：随媒体时长累积的时间坐标

`t` 不会把一段视频归一化到 `[0, 1]`。视频越长，其时间坐标跨度越大。

由于 H3 Video VAE 的时间压缩方式，连续 latent 帧的 RoPE 时间增量并不完全相等，而是循环使用：

```text
(5 / 3) * (1, 4, 4, 4, 4)
```

即增量约为：

```text
1.667, 6.667, 6.667, 6.667, 6.667, ...
```

在标准 24 fps 设置下，H3 的音视频时钟以约 40 个 RoPE 时间单位表示一秒，因此视频内的相对时刻可以近似换算为：

```text
elapsed_seconds = (t - video_origin_t) / 40
```

这里必须减去对应视频的起始坐标 `video_origin_t`。在 packed sequence 中，目标视频之前的文本 token、参考图片、参考音频和参考视频都会推进或偏移全局时间坐标。因此，`t` 是 packed 多模态序列中的媒体时钟，而不是可以直接当作现实时间戳的全局绝对值。

如果条件视频使用了不同的采样帧率，还应保证其 `t` 坐标跨度仍对应真实媒体时长；不能只按照 latent 帧序号生成时间坐标。

## 总结

| 轴 | 表达内容 | 是否随分辨率同比增长 | 是否随媒体时长增长 |
| --- | --- | --- | --- |
| `h/w` | 面积归一化的帧内空间位置 | 否 | 否 |
| `t` | packed 序列中的音视频时间 | 否 | 是 |

简而言之，`h/w` 是保留宽高比的相对空间坐标，而 `t` 是与真实媒体时长相关的累积时间坐标。
