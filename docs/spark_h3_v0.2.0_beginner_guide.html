Spark-H3 v0.2.0
小白安装指南

它是 MiniMax-H3 的 ComfyUI 加速节点：用块稀疏注意力减少采样阶段的计算量，让支持的 NVIDIA 显卡更快完成视频生成。

这一版最重要的 4 件事

① 不再替换官方 Kitchen
Spark 后端改为独立的 spark-h3-kitchen，可与 ComfyUI 官方 comfy-kitchen 共存。

② 默认推荐 0.2.37
发布测试中，它的速度和稳定性优于 0.2.39；小白保持默认即可。

③ 支持更多 ComfyUI 版本
覆盖 0.38.x–0.40.x 和 0.42.x–0.44.x；不支持 0.41.x。

④ Linux / Windows 六种包
RTX 30 / 40 / 50 系均有对应安装包，按系统和 GPU 架构选择。

独立 spark-h3-kitchen推荐 0.2.37RTX 30 / 40 / 50 系ComfyUI 0.38–0.40 / 0.42–0.44

安装 · 约 5 分钟
PART 1 · 安装

把 ZIP 放对位置，
再用“同一个 Python”安装

1关闭 ComfyUI，并解压到 custom_nodes

普通 / 虚拟环境安装

找到同时包含 main.py 与 custom_nodes 的 ComfyUI 根目录。

ComfyUI/
├── main.py
├── .venv/
└── custom_nodes/
    └── ComfyUI-Spark-H3/
        └── install.py

Windows 便携版

插件放在内层 ComfyUI\custom_nodes，不是最外层。

ComfyUI_windows_portable\
├── python_embeded\python.exe
└── ComfyUI\
    └── custom_nodes\
        └── ComfyUI-Spark-H3\
            └── install.py
解压正确的判断方法：打开 ComfyUI-Spark-H3 文件夹后，应直接看到 install.py，不能再套一层同名文件夹。

2使用启动 ComfyUI 的 Python 运行安装器

Windows 便携版（最常见）

在 ComfyUI_windows_portable 文件夹空白处打开 PowerShell：

.\python_embeded\python.exe .\ComfyUI\custom_nodes\ComfyUI-Spark-H3\install.py

Windows · .venv

.\.venv\Scripts\python.exe .\custom_nodes\ComfyUI-Spark-H3\install.py

Linux · .venv

./.venv/bin/python ./custom_nodes/ComfyUI-Spark-H3/install.py
不要直接双击 install.py，也不要随手输入系统 python。否则依赖可能装到另一个环境，终端显示成功，ComfyUI 却仍然找不到节点。
cu130 指 wheel 的编译版本。PyTorch CUDA 13.0 或更新版本可尝试安装；安装器会检查原生入口，更高版本仍需自行验证完整工作流。

3看到安装完成后，重启 ComfyUI

  1. 安装器默认安装独立的 spark-h3-kitchen 0.2.37；它不会替换、降级或锁定 ComfyUI 官方 comfy-kitchen。
  2. 从 v0.1.5 或更早版本升级时，安装器会先恢复曾被旧版覆盖的官方 Kitchen，再安装独立后端。
  3. 关闭终端并重新启动 ComfyUI；不要只刷新网页。然后把安装包内 workflows 中的 JSON 拖到画布。
为什么推荐默认 0.2.37？本次发布测试中，它的速度和稳定性都优于 0.2.39。除非你明确要做对比测试，否则不要添加 --kitchen-implementation 0.2.39。
如果实在不会安装：把下载好的 ZIP 安装包交给 WorkBuddy，让它按照本页步骤帮你安装；同时告诉它你的 ComfyUI 根目录、操作系统和显卡型号。

先用默认设置跑通，
再决定要画质还是速度

1选择与你显卡对应的节点

RTX 30 系

MiniMax H3 Spark Attention (SM86)

RTX 40 系

MiniMax H3 Spark Attention (SM89)

RTX 50 / PRO

MiniMax H3 Spark Attention (SM120)

2把节点接在模型加载器与采样器之间

模型加载器 → Spark Attention → BasicGuider / 采样器

最省心的方法是直接打开安装包自带工作流；旧版工作流也可以加载，参数会迁移到等价设置。

3只需要先认识这 4 个 mode

推荐

fidelity · 默认

前 20% 的采样调用保持 dense，之后使用 Spark。第一次使用、在意稳定与保真时先选它。

快

speed

关闭 dense warmup，从第一次调用就使用 Spark。更快，但建议先与 fidelity 对比结果。

手动

custom

保留你手动填写的 warmup 设置。修改正在生效的预热参数后会自动切到此模式。

对照

dense

完全绕过 Spark，等价于不连接 Spark 节点。适合排错或比较加速前后的耗时。

小白推荐：先保持 fidelity 与默认 topk_ratio=0.2；成功出片后，再复制一份工作流试 speed。

Ref2VA：sparse_scope 怎么选？

选项作用建议
target-video只稀疏目标视频；参考视频保持 dense/exact默认值，行为与 v0.1.3 一致
joint-video把多时间位置的参考视频与目标视频放入同一个 Spark 稀疏域带视频条件的 Ref2VA 推荐

静态参考图、文本、参考音频和目标音频在两种模式下都保持 exact。普通 T2V / I2V 工作流继续使用默认值即可。

dense_backend：dense 阶段用哪个后端？

kitchen · 包内自带

直接使用 spark-h3-kitchen 提供的 Kitchen INT8 Attention；不需要外接“模型注意力后端”节点。

inherit · 保持上游设置

不主动覆盖模型或其他节点已经选择的 attention 后端，适合兼容既有工作流。

最省心的用法：需要加速 fidelity 的 dense 预热或 dense 对照时，直接在 Spark 节点把 dense_backend 选为 kitchen；不需要再添加一个后端节点。
先跑通默认 fidelity，再尝试 speed；dense 是最实用的排错基线3 / 4
低显存 · 性能 · 排错
PART 3 · 用得更稳

显存不够怎么办？
出问题先查什么？

配合 KJNodes 低显存节点

先单独安装 ComfyUI-KJNodes，再按下面的顺序连接 MODEL。顺序很重要：Low VRAM Attention 必须放在 Spark 前面。

模型加载器 → Low VRAM Attention → Chunk FeedForward → Spark Attention → 采样器

先调 Spark

先逐步调低 producer_chunk；它只改变 Q/K/V producer 分块，不需要重新编译 wheel。

还不够再加 KJNodes

把 KJNodes 分块调小通常更省显存，但分块越小，执行开销可能越大。

历史 Linux 性能参考

GPUFidelity 相对 DenseSpeed 相对 Dense
RTX 3090（SM86）2.42×4.62×
RTX 4090（SM89）2.37×4.35×
RTX PRO 6000 Blackwell（SM120）2.05×3.15×

测试条件：Linux、ComfyUI 0.38.2、LightX2V 768p 8-step LoRA、1344×768、345 帧、24 FPS、topk_ratio=20%、warmup_steps=2；只比较采样耗时，不含模型加载、VAE 解码与视频编码。你的实际结果会因工作流、步数、权重和显存配置而变化。

遇到问题，按顺序检查

节点没有出现

  • 是否完整重启了 ComfyUI
  • install.py 是否在正确目录
  • 是否用了 ComfyUI 自己的 Python
  • 启动终端里是否有红色报错

提示没有匹配的 wheel

  • Linux / Windows 包是否选对
  • sm86 / sm89 / sm120 是否选对
  • 文件名是否包含 cu130
  • ComfyUI 是否为 0.38–0.40 或 0.42–0.44 系
  • Python 3.12+、PyTorch 2.12+、PyTorch CUDA 13.0+

运行时报错或结果异常

  • 先切到 dense 做基线
  • 再用默认 fidelity 测试
  • 后端先恢复为 inherit
  • 仅 fidelity OOM 时，尝试启动参数 --disable-cuda-malloc

速度没有想象中快

  • 只比较同一工作流的采样耗时
  • 确认没有回退到 dense
  • 尝试 speed 并对比质量
  • Ref2VA 视频条件是否用了 joint-video

最后的成功检查

能看到与显卡对应的 Spark 节点；默认 fidelity 能完成一次生成；切到 dense 也能完成；需要内置 Kitchen 时直接选择 dense_backend=kitchen，无需外接后端节点；两次测试使用同一工作流与输入时，才适合比较耗时。
